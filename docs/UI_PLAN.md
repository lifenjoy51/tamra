# Tamra UI 개선 계획

> 화면이 *기술 데모의 디버그 HUD*에 가까운 상태. 이를 *항해사가 보는 갑판*으로 전환하기 위한 기획서.

[ROADMAP.md](ROADMAP.md)의 Tier 1~3 진행과 병행. 가드레일은 [DESIGN.md](../DESIGN.md) "의도적으로 안 한 것" 준수.

---

## 1. 현재 UI 구성

**관찰**:
- 디버그 패널이 *기본 ON*이고 8줄 텍스트로 모든 정보가 동등 노출
- 미니맵은 *디버그 패널과 묶여* 있음 (`uiFlags.debugVisible` 단일 플래그)

- 페이지 로드 시 컨텍스트 전달 없이 바로 게임 진입

## 2. 기획 진단 — 문제 카테고리

### P1. "디버그 정보"와 "항해 정보" 혼재 (최우선)

`Wind`/`Cur`/`Sail`/`Ship`은 *플레이어가 알아야 하는 정보* — 5세기 항해사도 풍향·풍속·해류·돛 상태는 알았다.
`Tile`/`LatLon`/`FPS`는 *개발 디버그* — DESIGN.md 컨셉상 플레이어 시야에 노출되면 안 됨.

현재 구조: **둘이 같은 패널에 묶여 있어** "디버그 끄면 풍속도 안 보임" 또는 "디버그 켜면 좌표가 보여 컨셉 위반".

→ **분리 필수**. 항해 HUD(상시) + 개발자 패널(F1 같은 hidden toggle).

### P2. 미니맵의 정체성 모호

DESIGN.md L10 "미니맵·좌표·고정 방위 라벨 없음 (디버그 HUD는 개발용으로만 존재)" — 미니맵은 명시적 비전 위반 항목이지만, 현재 디버그 패널과 묶여 사실상 *상시 노출*되고 있다.

**기획 결정 필요**:
- (a) 미니맵 = 순수 디버그 → 기본 OFF, 개발자 패널과 함께 토글
- (b) 미니맵 = 시대 적합한 *해도(海圖)* 도구로 재포지셔닝 → 양피지 텍스처, 좌표 라벨 제거, "배 주변만" 흐릿하게 표현
- (c) 미니맵 제거 → Tier 3.4 환경 단서(새/부유물)로 대체

→ **추천: (a)**. 미니맵은 개발용으로 격하, 플레이어용 해도는 Tier 3 별 항목으로 신설(노트북/일지 형태).

### P3. 풍향·풍속이 숫자로만 표시

`Wind: 045° / 8.0 m/s`는 디버그 톤. 5세기 갑판에서 풍향을 알아내는 방법은:
- **마스트 꼭대기 천 조각/깃발** — 바람 방향으로 펄럭임 (동서양 공통 가장 오래된 풍향계)
- **얼굴/귀의 바람 감각** — 게임에선 표현 불가 → 깃발이 가장 현실적

→ **배 스프라이트에 펜넌트 추가** (마스트 위 작은 가로 천). `wind.angleRad - boat.angle` 상대각으로 펄럭 방향 결정. 풍속이 강할수록 더 수평으로 펄럭. 이 한 가지로 "현재 풍향 + 상대 풍각(AoA)"이 직관적으로 전달됨.

### P4. 돛 효율 시각 피드백 부재

`Sail: FULL 100% BEAM` 텍스트로만. IRONS(역풍 막힘) 상태인지를 *체감*하려면 돛 자체가 펄럭여야 함.

기존 자산: `audio.flapBurst()` 가 RUN(정후풍)에서 돛 펄럭 사운드를 이미 낸다. 시각도 동일 원리.

→ **돛 스프라이트의 변형/펄럭 애니메이션**:
- IRONS: 돛이 luff(앞뒤로 펄럭) — 회색조
- CLOSE/BEAM/BROAD: 정상적으로 부풂 — 밝은 흰색
- RUN: 가끔 펄럭 (audio와 동기)
- 돛 내림(`sail=0`): 돛 사라짐(말려있음)

### P5. 시각 시간 정보 부재

현재 우상단 `[8/15]` (월/일) 한 줄. 시각이 안 보인다 (낮/밤은 화면 밝기로 추정). 5세기 도구로 시간을 *완벽히* 알 수 없는 게 사실이지만, 최소한 *대략의 시각감*은 필요.

→ **태양/달의 위치 자체가 이미 시계** — 화면에 보이지 않을 때(흐림/실내 가정 없음)를 위한 보조: 우상단 텍스트를 `8/15  辰時`(약 2시간 단위 12지신 시각) 같은 *시대 적합* 표기. 또는 그냥 시 단위 (`8/15 14時`). 분 단위는 거짓이라 빼고.

### P6. 이벤트 알림 시스템 부재

일출/일몰 순간(Tier 3.2), 폭풍 진입(Tier 2.3), 좌초 임계(Tier 2.1), 도착 직전(Tier 1.1) — 모두 *순간*인데 알림이 없으면 놓친다.

→ **화면 중앙 상단 토스트 영역** (1줄, 3~5초 페이드). 톤: 객관적/관찰자 시점. 예:
- "해가 진다"
- "구름이 검어진다"
- "물결이 거칠다"
- "수심이 얕아진다"
- "육지가 보인다"

화살표·아이콘·점멸 같은 게임적 요소 최소화 — *항해 일지* 톤.

### P7. 시작 화면 / 컨텍스트 전달 부재

페이지 로드 → 바로 게임. 신규 플레이어는 자기가 누구이고 왜 항해 중인지 모름. 5세기 후반 탐라(476년 백제 조공 무렵) 분위기를 첫 1화면에 담을 기회 상실.

→ **타이틀 + 시나리오 브리핑 오버레이** (Tier 1.3와 직결). 타이포그래피만으로 충분 — 일러스트 없이도 흑단 배경 + 한자/한글 제호 + 1~3 문장 컨텍스트.

### P8. 인게임 도움말 부재

조작법은 README에만 존재. 첫 플레이어는 W를 눌러도 "왜 빨리 안 가지?"(역풍 모름).

→ **`?` 키 → 도움말 오버레이** (조작·돛 기본 원리·환경 단서 안내). 시간 정지(K 처럼). 첫 플레이 시 자동 1회 노출.

### P9. UI 패널의 시각 톤 통일성

현재 모든 패널이 `rgba(0,0,0,0.4)` + `border rgba(200,230,255,0.25)` + `font-family: ui-monospace` — 톤은 일관됨. **그러나** 5세기 항해 게임 분위기와 다소 어긋남(현대 SF/터미널 톤).

선택지:
- (a) 현재 미니멀 톤 유지 — 디버그스러운 인상 잔존
- (b) 양피지/먹/금속 광택 톤 — *시대감* 강화, 그러나 단일 HTML/Canvas 정신상 과한 asset 추가는 부담
- (c) 절충: monospace 유지 + 색조만 변경 (`#c8e8ff` 청회색 → `#d4c098` 양피지색), border를 갈색 톤으로

→ **추천: (c)**. CSS 변수 1~2개 변경으로 분위기만 슬쩍 옮긴다. 폰트·구조 변경은 Tier 1~3 완료 후.

### P10. 모바일 / 터치 — Tier 1 우선

기본 조작 모달리티가 터치/클릭이라는 설계 원칙상 *후순위가 아니라 즉시 우선*. 현재 상태:
- `#rudder-ui` 는 pointer 이벤트로 터치 가능 ✅
- `#sail-ui`/`#sky-ui`/`#toggle-ui` 는 클릭 가능 ✅
- **음소거(M) 클릭 UI 없음** ❌ — 키보드만으로 접근
- **시간 가속 컨트롤이 디버그 패널 안에 묶임** — 디버그 끄면 클릭으로 시간 가속 조절 불가
- 화면 <1024px 에서 패널 배치 보장 안 됨

→ **즉시 처리 (Tier A.4 신규)**: 음소거 버튼 추가, 시간 가속 컨트롤 분리, 모바일 미디어쿼리. ROADMAP Tier 1.4와 동일.

### P11. 로딩 화면 빈약

`<div id="loading">지형 데이터 로딩 중...</div>` — 검정 배경에 회색 텍스트. 첫인상이 약함.

→ **타이틀("탐라" 또는 "古代航海")을 같은 위치에 미리 표시**, 그 아래 작은 글씨로 로딩 메시지. 로딩 완료 시 fade out → 시작 화면으로 전환.

## 3. 가드레일 재확인

다음은 UI 개선이 침범하지 말아야 할 선:

| 거부 항목 (DESIGN.md) | UI 적용 |
|---|---|
| 나침반/방위 라벨 | 풍향을 ° 숫자로만 표시(현재) → 펜넌트로 *시각화* (방위 라벨 X) |
| 자동 항해/waypoint | 해도/일지에 "현재 위치" 점만 — 목적지까지의 *선* 그리지 말 것 |
| 별자리 연결선 | 하늘보기에서 별 이름 라벨 X (북극성만 별 고도 측정기 모드에서 *선택 시* 표시 — Tier 3.1) |
| 3D / WebGL | 모든 UI는 DOM + 단순 SVG/이모지/Canvas 2D |

**새 가드레일 (이 문서로 추가)**:
- 좌표(LatLon, gx/gy, tile xy)는 *플레이어 화면에 절대 노출 금지*. 개발자 패널(F1)에만.
- 게임 외부의 시각 어휘(아이콘 ⚡🌧️☁️ 등)는 가급적 *피하고* 짧은 한국어 텍스트로 (시대감).
- 알림 톤은 *관찰자/일지* 시점. "WARNING!", "DANGER!" 같은 게임적 표현 X.
- **키 라벨(W / S / K / M / [ / ] 등)을 플레이어용 화면에 노출하지 말 것**. 키보드는 디버깅/개발 편의용이며 기본 조작은 터치/클릭 — 키를 안내한다는 것 자체가 잘못된 신호. 디버그 패널 안에서만 허용.
- **모든 *플레이어* 액션은 클릭/탭 가능한 UI 컨트롤이 있어야 함**. 키보드 단축키는 *그 위의 보조*. 클릭 UI 없는 키 단축은 *디버그 전용*으로 한정.

## 4. 개선 제안 — Tier별

### Tier A. 기본 분리 (즉시, 작은 비용)

**A.1 항해 HUD ↔ 개발자 패널 분리**
- 항해 HUD (상시 ON): 풍향·풍속·돛 상태·지면 속도 (시각화 위주, 텍스트 최소)
- 개발자 패널 (F1 토글, 기본 OFF): Tile, LatLon, FPS, frame time, 미니맵
- `uiFlags.debugVisible` → `uiFlags.devPanel` 로 의미 명확화

**A.2 시작 화면 + 로딩 분리** ✅
- 로딩: 타이틀 큰 글자 + 작은 메시지
- 로딩 완료 → 시작 화면 ("항해 시작" 단일 버튼; 시나리오/계속하기는 후속)
- *조작법(키 안내) 항목 두지 않음* — 키보드는 디버깅용, 기본 조작은 터치/클릭이므로 키 라벨을 화면에 노출할 이유가 없음
- 화면 어디든 탭/클릭으로 게임 시작
- 구현: [src/ui/start-menu.ts](../src/ui/start-menu.ts)

**A.3 좌표 정보 게임 화면에서 제거**
- LatLon, Tile xy, gx/gy 노출 제거 (개발자 패널로 이동)

**A.4 누락된 클릭 컨트롤 보강** (격상)
- **음소거 클릭 버튼** — 현재 M 키만 존재, 클릭 UI 없음. sky-ui ★ 옆에 추가 권장.
- **시간 가속 컨트롤 분리** — 현재 디버그 패널 안에 묶여 디버그 끄면 클릭으로 시간 조절 불가. 플레이어용으로 격상하거나 별도 토글.
- **모바일 미디어쿼리** — `<1024px`/`<640px` 분기, 패널 위치·크기 자동 조정.
- 회전/이동 스텝(`[`/`]`/`,`/`.`)은 디버그성 키이므로 클릭 UI 필수 아님 — 디버그 패널 안 컨트롤로 흡수만 권장.

비용: 小~中.

### Tier B. 시각화 강화 (중간 비용)

**B.1 펜넌트 (P3)**
- `boat.png`에 마스트 추가하거나, 별도 sprite layer로 펜넌트 그리기
- 매 프레임 `wind.angleRad - boat.angle` → 펜넌트 회전·펄럭 진폭

**B.2 돛 시각 변형 (P4)**
- 돛 스프라이트를 `boat.sail` × `sail.mode` 매트릭스로 분기 (이미지 N장 또는 절차 변형)
- 또는 boat.png 위 별도 돛 캔버스 레이어

**B.3 토스트 알림 (P6)**
- DOM `<div id="toast">` 1개. 큐 + 페이드. 게임 시간 기준 표시 (실제 시간 3~5초)
- 트리거 후크: 일출/일몰/폭풍/좌초/도착 등은 각 시스템에서 `toast("...")` 호출

비용: 中. 스프라이트/CSS 추가, 알림 큐 모듈.

### Tier C. 시대감 (중간~큰 비용)

**C.1 시각 톤 정돈 (P9)**
- CSS 변수화 + 색조 양피지 계열
- 디바이더·테두리 현재보다 미세하게 "오래된" 느낌

**C.2 시각·날짜 표기 (P5)**
- 우상단을 `8月15日 辰時` 류로
- 12지신 시각표기는 옵션 (서구 시각으로 fallback 가능)

**C.3 도움말 오버레이 (P8)**
- `?` 키 → 시간 정지 + 반투명 오버레이
- 조작법 + 돛 기본 + 환경 단서 (펜넌트 보는 법) 1~2 화면

**C.4 해도(海圖) 도구 (P2 — Tier 3과 결합)**
- 미니맵 대신 *수동 일지 형태*
- L 키로 토글 (Tier 3.3 일지와 통합)

## 6. 검증 방법

- 신규 플레이어가 *디버그 끄지 않은 상태*로 시작해도 *항해 정보*가 모두 보이는가
- *디버그 켜지 않은 상태*에서 좌표·LatLon·tile·FPS가 *전혀* 안 보이는가
- 풍향을 펜넌트만 보고 인지 가능한가 (텍스트 가린 채 테스트)
- 모든 토스트 메시지가 관찰자 톤인가 ("DANGER" 같은 표현 없음)
- 첫 키/클릭 전 게임이 시작되지 않는가 (시작 화면 게이트)
- 가드레일 침범 항목(좌표 노출, 별자리선, 자동 항해선)이 없는가
