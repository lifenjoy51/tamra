# Tamra 로드맵

> 환경 시뮬은 완성됐다. 이제 *게임*을 만들 차례다.

이 문서는 "왜 이 작업이 필요한가"의 기획 의도와 우선순위를 담는다.
구현 디테일은 [CLAUDE.md](../CLAUDE.md), 설계 배경은 [DESIGN.md](../DESIGN.md), **시대(5세기 후반) 항해술 사실 근거는 [PERIOD_NOTES.md](PERIOD_NOTES.md)**, **항구·교역망·시나리오 항로 근거는 [TRADE_NETWORK.md](TRADE_NETWORK.md)** 참조 — 새 시나리오/항법 도구 작업 전 반드시 확인.

## 현황 진단

**완성된 것** — Vite+TS 모듈화, 8,496 해안선 타일 스트리밍, 천체역학(태양·달·7행성·~70 별), 대기 대순환 풍·쿠로시오·파도 3층, 날씨/구름/비/뇌전, 돛 polar curve + rudder 관성, Web Audio 절차생성, 배포 파이프라인.

**비어 있는 것** — 게임 목표, 실패 조건, 진행감, 항해 동기, 스토리 컨텍스트, 항법 보조 도구, 시작/엔딩.

**진단**: 현재 Tamra는 *기술적으로는 완성된 시뮬레이터*지만 *게임으로서는 출발 직전*. 플레이어는 어딘가에서 시작해서 어디로든 갈 수 있지만, 왜 가야 하는지·언제 끝나는지·실패할 수 있는지가 없다.

## 비전 가드레일 ([DESIGN.md](../DESIGN.md) "의도적으로 안 한 것" — 침범 금지)

다음은 의도적으로 거부된 항목들이다. 새 기능이 이것들과 충돌하면 *기능을 포기하거나 우회하는 것이 정답*:

- **나침반/방위 라벨** — "배 위의 사람" 컨셉 위반
- **자동 항해 / waypoint 길찾기** — 시뮬은 길찾기를 *경험*하는 것
- **별자리 연결선** — 별 패턴 인지 학습 과정 보존
- **3D 배 모델 / WebGL** — Canvas 2D 단일 HTML 정신 유지

→ 게임 목표와 항법 보조는 이 선을 우회해서 설계해야 한다 (예: 항법 도구는 "별 고도 측정기" 같은 *시대 적합한* 도구로, 자동 길찾기 대신).

## Tier 1 — 게임 루프 (없으면 게임이 아님)

### 1.1 시나리오 모드 — 출발지·목적지 도착

**왜**: 현재 `tilesInit.startGx/Gy/Angle`([src/main.ts](../src/main.ts))은 무작위 해안선. 플레이어는 어디 있는지·어디로 가는지 모른다. 시뮬레이터를 게임으로 만드는 가장 작은 단위는 *출발과 도착*이다.

**무엇** (난이도 순. 사료 신뢰도와 *릴레이형 항로* 구조 반영 — 근거: [TRADE_NETWORK.md](TRADE_NETWORK.md)):
- **탐라 ↔ 흑산도** — 단거리 입문용 (보조 노드).
- **탐라 → 영산강 하구**(목포·영암·해남) — *가장 안정적 근접 교역축*. 마한·백제계 재분배항.
- **탐라 → 가야 김해**(봉황동·대성동) — 높은 신뢰도. 철·국제 위신재 동기.
- **탐라 → 북규슈**(대마-이키 경유 → 무나카타) — *경유 릴레이 구조 명시*. 단일 직항이 아닌 다단계.
- **탐라 → 백제 웅진**(공주 인근 금강 하구) — 476년 조공 사절선 모티프. 시대 앵커 직결.

**보류** (1차 시나리오에서 제외 — 사료상 *백제·왜 매개*가 본질):
- 탐라 → 남조(명주·건강·광저우) 직항 — 후속 다단계 시나리오로만.
- 오키나와·사할린 등 변연 노드 — 직접 항로 증거 부족.
- 각 시나리오: 시작 좌표/계절/시간 + 도착 판정 영역(반경 N km).
- 시작 시 화면에 1회 텍스트 브리핑(역사 컨텍스트 + 풍향 힌트) → 페이드아웃.
- 도착 시 결과 화면(소요 시간·평균 속도·항로 일탈도).

**기존 자산 활용**: `tile_index.json`(8,496 해안선 타일)으로 항구 후보 셀 고를 수 있음. `boat.gx/gy` 추적은 이미 있음.

**개발 비용**: 中. 시나리오 데이터 + 시작/도착 UI + 결과 화면.

### 1.2 자유 항해 모드

**왜**: 시나리오와 별개로 "그냥 떠나고 싶다"는 욕구. 현재 디폴트가 이미 자유 항해이므로 *모드 분기*만 필요.

**무엇**: 메인 메뉴에서 "시나리오 / 자유 항해" 선택. 자유 항해는 발견한 해안 구역·통과한 해류대를 일지(log book)에 누적.

**개발 비용**: 小. 메뉴 + 모드 플래그.

### 1.3 메인 메뉴 + 시작 화면 ✅ (1차 완성, 시나리오/계속하기는 후속)

**왜**: 현재 페이지 로드 직후 바로 게임에 던져진다([src/main.ts](../src/main.ts)). 게임의 *시작*이 없다.

**무엇**: 단순한 메뉴(시작/시나리오 선택/계속하기). 단일 HTML 정신상 별도 라우팅 없이 같은 캔버스 위 오버레이. *조작법(키 안내) 항목은 두지 않는다* — 키보드는 디버깅용이고 기본 조작은 터치/클릭이므로 화면에 키 라벨을 노출할 이유가 없음.

**현재 상태**: 단일 "항해 시작" 메뉴 + 양피지 톤 타이틀 구현됨([src/ui/start-menu.ts](../src/ui/start-menu.ts)). 시나리오 선택과 "계속하기"는 1.1·5.4와 함께.

**개발 비용**: 小.

### 1.4 터치/클릭 우선 인터페이스 보장 (격상)

**왜**: 키보드는 *디버깅 전용*이며 기본 조작은 터치/클릭(설계 원칙). 현재 sail/rudder/sky/toggle은 클릭 가능하지만 (a) M(음소거) 등 일부 액션이 클릭 UI 없이 키 단축만 존재, (b) Time/Map 컨트롤이 *디버그 패널 안*에 있어 디버그 끄면 클릭으로 시간 가속 조절 불가, (c) 모바일 화면(<1024px)에서 패널 위치/크기 보장 없음.

**무엇**:
- **음소거 클릭 버튼** 추가 (sky-ui ★ 옆 또는 별도). 1차로 구현.
- **시간 가속 컨트롤을 디버그와 분리** — 플레이어용 액션이므로 상시 노출. 미니맵 축척은 디버그성이라 패널 안 유지.
- **모바일 미디어쿼리**: `<1024px`/`<640px` 분기로 패널 위치·크기 자동 조정. rudder-ui 너비, sail-ui 세그먼트 폭 등.
- 회전/이동 스텝 등 *디버그성* 키 단축은 그대로 두되, 디버그 패널 안 클릭 컨트롤 보강.

**기존 자산**: sail-ui, rudder-ui, sky-ui 클릭 패턴 재사용.

**개발 비용**: 中.

## Tier 2 — 위험과 진행감 (긴장감)

### 2.1 좌초 판정 + 데미지

**왜**: 현재 3x3 shore buffer([src/render/camera.ts](../src/render/camera.ts) `moveBoat`)로 *육지에 부딪치면 진입을 막는* 정도. 충돌 자체에 대한 *결과*가 없다 → 해안선 갈아내기가 위험 없는 무료 행동.

**무엇**:
- 충돌 시 선체 데미지(0~100). 30 누적부터 침수 속도 페널티, 100에서 좌초 종료.
- 얕은 수심(SEA-N ~ SEA) 진입 시 미세 데미지 누적(rocks/reef 가정).

**기존 자산 활용**: `altitude` 버퍼와 `SEA=64` 임계값 이미 있음.

**개발 비용**: 小~中.

### 2.2 식수·식량 (선택적, 토글 가능)

**왜**: 5세기 항해의 *진짜* 제약은 보급. 무한 항해 가능하면 거리/시간이 추상적인 숫자가 된다.

**무엇**:
- 출발 시 보급량(예: 식수 14일치). 게임 시간 흐름에 따라 소진.
- 시나리오마다 권장 보급 표시 → 부족 시 표류 위험 부각.
- 자유 항해/입문자 위해 *Off* 토글 제공.

**개발 비용**: 小. 카운터 + UI 한 줄.

### 2.3 폭풍 데미지

**왜**: 현재 `weather.cloudiness`/`precipitation`/뇌전([src/render/effects.ts](../src/render/effects.ts))은 *시각 효과로만* 존재. 플레이어 의사결정에 영향이 없다.

**무엇**:
- `cloudiness > 0.85 && wind.speedMS > 12` 폭풍 상태 → 돛 펴면 데미지 누적, 돛 내리면 안전(대신 표류).
- 멀리서 보이는 어두운 구름 띠 = 회피 신호 (*환경 단서로 위험 예측*).

**개발 비용**: 小. 기존 weather 시스템 위 1 phase 추가.

### 2.4 표류 상태

**왜**: 무풍대(적도 무풍대·고기압대) 진입은 역사적 위험. 현재는 "느려진다" 외에 의미 없음.

**무엇**:
- `wind.speedMS < 1.5 && boat.sail > 0` 30분 게임 지속 시 "표류" 알림 + 식수 소비 가속.
- 해류 drift만으로 빠져나갈 수 있도록 보장(현 `current` 시스템 활용).

**개발 비용**: 小.

## Tier 3 — 항법 보조 도구 (시대 적합한 한도 내)

> ⚠️ 가드레일: 현대식 나침반/GPS/자동 항해 금지. 자기 나침반은 11세기 이후이므로 5세기 항해사가 *실제로* 사용한 도구만 (별·태양·새·해류·해안선 형태).

### 3.1 별 고도 측정기 (Kamal 류)

**왜**: 별의 지평선 위 고도는 위도와 직결. 5세기 동아시아 항해사도 손가락 폭·기준 별 같은 단순 도구로 위도 가늠. 현 시스템은 별 고도를 *내부적으로 알고 있지만*(`starState[i].altRad`) 플레이어가 읽을 방법이 없다.

**무엇**:
- 키보드 N(예) 입력 시 화면 중앙 십자선 + 별 선택 → 그 별의 현재 고도(°) 표시.
- 북극성을 측정하면 = 그 자리의 위도. 시간차로 다시 측정 → 위도 변화량 = 남북 진행거리 추정.

**개발 비용**: 中. 별 선택 UI + 십자선 + 측정값 표시.

### 3.2 일출/일몰 방위 표시

**왜**: 일출 방위는 *위도와 계절의 함수*. 항해사 경험으로 "여름의 일출은 정동에서 N도 북쪽" 같은 감각이 있었음.

**무엇**: 일출/일몰 순간 화면 가장자리에 작은 마커(점) 짧게 표시(2~3초). 현대식 라벨 아님 — 그냥 *순간을 놓치지 않게* 도와주는 정도.

**개발 비용**: 小.

### 3.3 항해 일지 (Log Book)

**왜**: 5세기 동아시아 항해사도 죽간/목간에 기록을 남겼다. 플레이어 *기억 보조*는 시대 적합.

**무엇**:
- 키보드 L → 일지 패널 토글.
- 자동 기록: 출발 시각/위치, 1시간(게임)마다 시각·풍향·돛모드·이벤트(폭풍/별 측정/좌초).
- 수동 노트는 v2.

**개발 비용**: 中.

### 3.4 환경 단서 강화

**왜**: 새의 비행 방향, 부유물의 흐름, 바닷물 색 변화는 5세기 항해사 핵심 단서. 현재는 없음.

**무엇** (점진):
- 해안 N km 이내 진입 시 새 스프라이트 1~3마리 (육지 방향에서 날아옴).
- 해류 강한 셀에서 부유물(나뭇가지) 1~2개 렌더 (drift 방향 시각화).
- 강 하구 인근 바다색 미세 변화(이미 colormap에 적용 가능).

**개발 비용**: 中. 신규 sprite 시스템 + sky/effects 합류.

## Tier 4 — 콘텐츠 / 스토리

### 4.1 5세기 후반 탐라 역사 컨텍스트

**왜**: "왜 5세기 후반 탐라인가?"가 게임 안에서 전달되지 않는다. *476년 탐라가 백제에 조공하며 동아시아 해상 네트워크에 공식 편입된 사건*이 시대 앵커이지만, 이 맥락이 플레이어에게 닿지 않으면 단순 시뮬에 머문다.

**무엇**:
- 시나리오 브리핑에 1~3 문장 역사 컨텍스트:
  - 탐라국과 백제 부용 관계 (476년 조공)
  - 백제 웅진 천도(475) 직후 정세
  - 왜 5왕(478년 왜왕 무→남조 송 표문) 시기의 동아시아 해상 외교
  - 백제 매개의 남조 송/제 통교
- 도착 시 그 항구의 역사 단편 1~2 문장.
- 톤: 과시적이지 않게, 짧게. *9세기 이후 인용 금지* (장보고/청해진 등 시대 미스매치).

**개발 비용**: 小. 텍스트 데이터.

### 4.2 항구/포인트 데이터

**왜**: 시나리오 모드의 도착지·경유지 정의에 필요.

**무엇**: `data/ports.json` — 이름·좌표·시대·역할·신뢰도·탐라와의 관계. **근거 문서: [TRADE_NETWORK.md](TRADE_NETWORK.md) 항구 노드 데이터 표** (탐라/영산강/김해/대마/이키/무나카타/난바/백제 웅진/건강/광저우/흑산도 등). 도착 판정 영역(반경 N km).

**가드레일**: 자료의 *간접 연결* 노드(오키나와·사할린)는 직접 항로로 만들지 말 것. 탐라 수출품은 *추정* 표기 의무 (해산물·패각·가죽류).

**개발 비용**: 小. 자료조사는 TRADE_NETWORK.md로 대부분 완료.

`Render()` 2.33ms / 50ms cap → 30ms+ 여유. 새 시스템(Tier 2~3) 추가 시 예산 안에서 운용. 별도 최적화는 *불필요*.

### 5.4 세이브/로드

자유 항해 진행 보존. localStorage 충분. 우선순위 低 (Tier 1.3 이후).

## 추천 진행 순서

0. **Tier 1.3 (메뉴) ✅ 1차 완성** — 시작 화면 + 양피지 톤 적용 완료.
1. **Tier 1.4 (터치/클릭 보장) + 1.1 (시나리오 1개)** — 음소거·시간 가속 등 클릭 컨트롤 보강 + 가장 짧은 시나리오(탐라↔흑산도 ~70km) 1개로 *게임 루프*가 닫히는 것을 먼저 확인.
2. **Tier 2.1 (좌초) + 2.3 (폭풍)** — 진짜 위험 도입. 같은 항로가 *일관된 결과*가 아니게 된다.
3. **Tier 3.1 (별 고도) + 3.3 (일지)** — 위험 대응 도구 제공. *항해사 감각* 시뮬 핵심.
4. **Tier 1.1 항로 확장 + Tier 4** — 컨텐츠 풍부화.
5. **Tier 2.2/2.4 + Tier 3.2/3.4 + Tier 5** — 디테일.

각 Tier 1~3 단계가 끝날 때마다 *플레이테스트*를 해서 다음 우선순위를 다시 정한다 (게임 기획은 한 번에 결정하지 않음).

## 검증 방법

- 각 시나리오를 끝까지 *플레이* 가능한가 (no-stuck, no-soft-lock).
- 좌초/폭풍/표류가 의사결정을 바꾸는가 (단순 데미지 표시 아닌가).
- 항법 도구 없이도 클리어 가능한가 (도구는 *보조*이지 필수가 아님).
- 비전 가드레일을 침범하지 않는가 (코드 리뷰 시 체크리스트).
